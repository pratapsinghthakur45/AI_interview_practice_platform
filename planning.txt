# AI Interview Platform — InterviewAI

## 1. Project Goal

InterviewAI is an AI-powered interview practice platform where candidates can practice realistic interviews before their actual interview.

The platform should:

* Ask questions based on the candidate's profile.
* Use the candidate's resume as interview context.
* Optionally use a Job Description (JD).
* Allow Technical and HR/Behavioral interviews.
* Allow Easy, Medium, and Hard difficulty.
* Analyze the candidate's answers.
* Ask relevant follow-up/counter questions.
* Adapt subsequent questions based on previous answers.
* Avoid repeatedly asking the same questions.
* Generate a detailed performance scorecard after the interview.

The goal is **not** to simply call an LLM and generate random questions.

The goal is to build an **adaptive, context-aware, multi-agent interview system**.

# 10. Interview Conversation

This is an important part missing from the original plan.

You need to store the questions and candidate answers.

Instead of putting everything directly inside the Interview document, use an `InterviewMessage` or `InterviewTurn` collection.

Recommended:

```text
InterviewTurn
├── interview
├── question
├── answer
├── questionType
├── sequence
├── evaluation
└── createdAt
```

Example:

```text
Interview
   │
   ├── Turn 1
   │      ├── Question
   │      └── Answer
   │
   ├── Turn 2
   │      ├── Question
   │      └── Answer
   │
   └── Turn 3
          ├── Question
          └── Answer
```

This gives the AI the conversation history it needs.

# 12. Technical Interview Agent

The Technical Agent should not randomly generate questions.

It should consider:

```text
Candidate Resume
+
Job Description
+
Candidate Profile
+
Difficulty
+
Previous Questions
+
Previous Answers
```

For example:

Resume:

```text
MERN E-commerce Project
JWT
MongoDB
Razorpay
```

JD:

```text
Node.js
REST API
MongoDB
Authentication
```

The agent might ask:

```text
Explain how you implemented authentication
in your MERN application.
```

After the candidate answers:

```text
Candidate Answer
       ↓
Answer Evaluation
       ↓
Missing concept identified:
JWT verification middleware
       ↓
Follow-up question
```

This is the behavior you want.

# 14. Interview Orchestrator

This is the agent responsible for controlling the interview flow.

```text
                    Interview State
                          │
                          ▼
                    Orchestrator
                          │
             ┌────────────┴────────────┐
             │                         │
             ▼                         ▼
      Technical Agent             HR Agent
             │                         │
             └────────────┬────────────┘
                          ▼
                  Candidate Answer
                          │
                          ▼
                   Answer Analysis
                          │
                          ▼
                    Orchestrator
                          │
                          ▼
                  Next Question
```

The orchestrator decides:

* Which agent should act.
* Whether a follow-up is needed.
* Whether to move to a new topic.
* Whether the interview should continue.
* When the interview should end.

This is where LangGraph becomes useful.

```text

          └────────┬────────┘
                   ▼

                   │
                   ▼
```

```text
          └── Difficulty
                   │
                   ▼

             ┌─────┴─────┐
             ▼           ▼
        Technical       HR
          Agent         Agent
             │           │
             └─────┬─────┘
                   ▼
```
